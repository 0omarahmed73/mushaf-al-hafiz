# Data Model: Mushaf Reader, Wirds and Reminders

Two kinds of data: **Quran data** (read-only, bundled, generated by `tool/build_quran_assets.py`, format
in [contracts/assets.md](./contracts/assets.md)) and **user data** (on-device SQLite via drift).

## Quran data (read-only)

| Entity | Fields | Rules |
|---|---|---|
| **Page** | `page` 1–604, `juz` 1–30, `hizbQuarter` 1–240, `lines` | Pages 1–2: 8 lines; 3–604: 15 lines. juz/quarter = those of the page's first ayah word. |
| **Line** | `n` (1-based on the page), `type` ∈ {ayah, surah_name, basmallah}, `centered`, `surah` (only on surah_name), `words` | `words` empty unless `type = ayah`. |
| **Word** | `id` 1–83,668, `k` "s:a:w", `g` glyph | Every id appears exactly once, in increasing order across pages and lines. `surah`, `ayah` parsed from `k`. Ayah-end markers are words. |
| **Surah** | `n` 1–114, `name` (Arabic), `ayahs`, `startPage` | 114 entries; surah 18 → startPage 293. |
| **Lookup tables** | `pageJuz[604]`, `pageHizbQuarter[604]`, `pageSurahs[604]`, `ayahPage{"s:a"}` | `ayahPage` has 6,236 keys; `"2:255" → 42`. |

## User data (drift / SQLite)

### Wird

| Field | Type | Rules |
|---|---|---|
| id | int, PK, autoincrement | |
| name | text | non-empty |
| type | text enum `reading` \| `hifz` \| `review` \| `qiyam` | only `reading`, `qiyam` creatable in this feature |
| currentPage | int | 1–604, default 1; writes outside the range throw `ArgumentError` |
| dailyPages | int? | ≥ 1 when set; wins over targetDate |
| targetDate | date? | date only |
| khatmaCount | int | default 0, increments on completing page 604 |
| notifyEnabled | bool | default: on for reading, off for qiyam |
| notifyMinutes | int? | minutes after local midnight; default 1200 (20:00) when turned on |
| color | int | one of 8 palette colours |
| sortOrder | int | list order |
| createdAt | datetime | |

### WirdDay (today's portion)

| Field | Type | Rules |
|---|---|---|
| wirdId | int, FK → Wird (cascade delete) | |
| day | text `yyyy-MM-dd` | wird day: local calendar date for reading; for qiyam the date of the night (00:00–03:59 belongs to the previous date) |
| startPage | int | wird position when the day's portion was first needed |
| endPage | int | `min(startPage + pagesPerDay − 1, 604)` |
| done | bool | default false |
| PK | (wirdId, day) | one portion per wird per local day |

**State transitions** (per wird per day):

```
(none) --first needed today--> open(start=A, end=B)
open --«تم»--> done      [if currentPage ≤ B: currentPage = B+1; if B = 604: currentPage = 1, khatmaCount += 1]
open --currentPage > B--> counts as done (isDone), row may stay done=false
next wird day --> new row from the position at that time
open --goal edited--> endPage recalculated from startPage (done rows keep theirs)
any --start page edited--> currentPage = new start; an open row is recreated from it
```

### Setting (key/value text)

| Key | Value | Default |
|---|---|---|
| `activeWirdId` | wird id or empty | id of «الورد اليومي» |
| `lastViewedPage` | 1–604 | 1 |

### Defaults created by `ensureDefaults()` (idempotent)

One wird: name «الورد اليومي», type reading, currentPage 1, dailyPages 20, notifyEnabled true,
notifyMinutes 1200, active. Settings as in the table above.

## Derived values (pure functions, `lib/wirds/portion.dart`)

- `pagesPerDay`: dailyPages if set; else `ceil((604 − currentPage + 1) / max(1, daysInclusive(today, targetDate)))`
  if targetDate set; else 20.
- `portionFor(start, perDay)` → `(start, min(start + perDay − 1, 604))`.
- `wirdDayKey(type, localNow)` → `dayKey(localNow)` for reading; `dayKey(localNow − 4 h)` for qiyam.
- `isDone(day, currentPage)` → `day.done || currentPage > day.endPage`.
- `afterDone(endPage)` → `endPage < 604 ? (endPage + 1, false) : (1, true)`.
