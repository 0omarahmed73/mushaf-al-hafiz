## Once Only: When the Popup Opens and When It Must Not

- [ ] CHK001 Is «first launch» defined by something observable (an empty stored state) rather than by "the first time", and is the consequence for a person who updates from an older version stated? [Clarity, Spec §Clarifications, §Assumptions]
- [ ] CHK002 Is the moment the popup opens measurable (after the first frame, within a time) and tied to the splash of feature 009 without depending on how that splash is built? [Measurability, Spec §FR-001, §FR-002, Research D12]
- [ ] CHK003 Are all the ways the popup can close listed, each with its effect on the stored state (finish, skip, back, a touch outside, a programmatic close, the app killed)? [Completeness, Spec §FR-006, Research D4]
- [ ] CHK004 Does the spec say why a touch outside the card does nothing, so that a reviewer can tell it is deliberate and not an omission? [Clarity, Spec §Clarifications, §FR-002]
- [ ] CHK005 Is «never again» defined for each way the app can start again (a new process, a rebuilt screen, a restored backup, a cleared cache), with the exception named (cleared data)? [Coverage, Spec §SC-001]
- [ ] CHK006 Are the failure modes of the stored state specified in both directions (cannot read: no popup; cannot write: popup still closes and may come back) and are they consistent with Constitution II and VII? [Completeness, Spec §FR-007, Research D3]
- [ ] CHK007 Is the rule for a value that is present but not `'true'` stated, so that a damaged or unexpected value has one defined meaning? [Gap, Data model, Research D3]
- [ ] CHK008 Is the case «a second popup while one is open» specified for both callers (the gate re-created, a second call of the function)? [Coverage, Spec §FR-009, Research D11]
- [ ] CHK009 Is the rule «the flag is read once, never followed live» written with its reason, and is it consistent with the plan's test technique? [Consistency, Spec §FR-007, Research D2, D14]
