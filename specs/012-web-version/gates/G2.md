# G2: which storage does drift pick on the web (COOP/COEP off), and what happens with two tabs?

| Field | Value |
|---|---|
| Gate | G2 (research D5, «Early gates») |
| Date | 2026-11-21 |
| Command | `python3 tool/web_smoke/gate_g2_storage.py $GATES/g2_storage --work $GATES/g2_work --url http://127.0.0.1:8766` (probe app in the scratchpad, `drift 2.35.4`, `drift_flutter 0.3.1`, `sqlite3.wasm` and `drift_worker.js` of the spike copy; served by `python3 -m http.server` which sends no COOP/COEP, like the real host) |
| Engines | Chromium (headless, playwright-core, cached chromium-1255). Firefox: **not run**. WebKit: **not run** (no engine installed, no download approved, T002). Chrome on the owner's phone: **not run** (needs the owner's phone, G5/owner check later) |
| Measured numbers | Store chosen by drift: **`sharedIndexedDb`** (`crossOriginIsolated` false; `missingFeatures` = `dedicatedWorkersInSharedWorkers` + `sharedArrayBuffers`, which is the expected result without isolation). `navigator.locks` exists, `navigator.storage.getDirectory` exists. Persistence: tab A wrote 5 rows, after a reload the count was 5. Two tabs of the same origin writing at once (30 rows each, 60 ms apart): **60 of 60 writes succeeded, 0 errors, no blocking**, the final read from a third tab: A = 35, B = 30 (nothing lost, nothing duplicated) |
| Verdict | **PASS on Chromium** (durable store chosen, two tabs did not corrupt or block each other); **not established for Firefox and WebKit** |
| Consequence for the plan | (1) `StorageStatus` mapping (data-model.md `StorageStatus`): `sharedIndexedDb`, `opfsLocks`, `opfsShared` -> `durable`; `unsafeIndexedDb` -> `unsafeShared` (or `durable` when the Web Lock guard is available); `inMemory` -> `volatile`. (2) On Chromium drift's shared worker already serializes two tabs, so the Web Lock one-tab guard (plan decision 5) is **not needed to prevent corruption here**; it stays as decided by the owner because (a) the engines where drift falls back to `unsafeIndexedDb` (not run here) can corrupt, and (b) two tabs still keep separate in-memory app state (the second tab would show stale wirds until reloaded). The plan is unchanged; the guard's test cases still cover it. (3) Because COOP/COEP stay off, adding them later would switch the store to OPFS and make existing readers' data look empty: the decision is made once (D5) |
