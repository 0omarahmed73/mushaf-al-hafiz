# G3: `--wasm` (skwasm) versus the normal JS build (CanvasKit)

| Field | Value |
|---|---|
| Gate | G3 (research D6, «Early gates») |
| Date | 2026-11-21 |
| Command | `python3 tool/web_smoke/gate_g3_wasm_vs_js.py $GATES/g1_fontloader --work $GATES/g3_work --url http://127.0.0.1:8767` (the G1 probe plus its `mode=turns`; both builds with `--no-web-resources-cdn`; the wasm build adds `--wasm`; served by `python3 -m http.server`, localhost, no throttling) |
| Engines | Chromium (headless, playwright-core, cached chromium-1255). Firefox and WebKit: **not run** (no engine installed, no download approved). The owner's phone: **not run** (G3 is repeated on the real app in Phase 11, and the owner's phone check comes later) |
| Measured numbers | Pixels, pages 1, 2 and 50 (WOFF2 fonts, 412x700): **0 differing pixels** between the JS and the wasm build. First paint of page 1 (navigation to the frame after the glyphs, median of 3 runs): JS 299 ms, wasm **194 ms**. 20 page turns (fetch of font and layout, font registration, drawing frame; 3 runs x 20): median JS 86 ms, wasm **48 ms**; p90 JS 109 ms, wasm 56 ms. No error in any run |
| Verdict | **PASS** on Chromium: equal pixels and not slower (faster) |
| Consequence for the plan | `--wasm` stays (plan decision 6). The numbers are for a probe on localhost (no network cost) and say nothing about absolute speed on a phone; re-run on the real app in Phase 11 and on the owner's phone. Any pixel difference there sends the build to the normal JS build (a flag in `tool/build_web.sh`, nothing else) |
